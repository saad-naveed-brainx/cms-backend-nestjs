## Summary

Stack: NestJS (TypeORM, Zod validation, Vitest E2E).

Scope: Extends the `npm run demo` CLI (users-roles T8 follow-up to T3) so each demo client's `content.json` can list **people** (Editor, Author, Contributor, Viewer) and **credit pages to an author**. The command adds people through the real `InvitationsService` + `InvitationAcceptanceRepository` (new user → generated 24-char base64url password printed once; existing user → direct acceptance repo path with `kind: 'existing'`, password unchanged), then creates and publishes each credited page as that person using their real role's permissions (loaded via `SiteMemberRepository.findAccess`). Pre-write validation (`checkCredits` superRefine) refuses an author not in `people`, an author whose role cannot publish (only Editor/Author allowed by `CREDITED_ROLES`), the Home page having an author, or duplicate emails in `people`.

The test file now mocks `NestFactory.createApplicationContext` so `runDemo` exercises its real `openNestApp` path (removing the previous fourth-argument injection and the parallel service list that could drift from `openNestApp`); a new `[UC-UR-27]` verifies all four roles land on each site, each generated password appears exactly once in the output and opens its account's stored hash, `--replace` reuses the same accounts and prints "existing account, password unchanged" per person, and all accounts can sign in after both runs. Docs (`CLAUDE.md`, `demo/README.md`) describe the new behaviour.

No cross-repo contract changes — this is API-only.
