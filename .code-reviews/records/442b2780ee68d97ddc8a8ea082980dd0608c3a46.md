## Summary

Stack: NestJS. Scope: version-history T1 — read-only routes for page versions.

Adds the versions desk (`RevisionRepository` extending `ScopedRepository`, read-only), two new routes under `ContentController` (`GET /content/:id/versions` and `GET /content/:id/versions/:versionId`), paging input (`versionsQuery`), snapshot projection (`toVersion`/`toVersionRow`), and the shared `requireEditRight` helper (extracted from `update`). Writing versions is deferred to T2.

Isolation guarantees are preserved: `findById`/`findOneWhere` on `ScopedRepository` scope every read by `siteId`; the raw-SQL join in `saversOf` is parameterized and scopes through `revisions` on `site_id`, mirroring the established `authorsOf` pattern in `content.repository.ts`. Access decisions (404 before 403) match `update`. Snapshot projection defensively handles an older-shape row by typing every field. Tenant-isolation and organization-isolation sweeps are extended to include both new routes, and tenant-isolation's `disposable()` now produces a version so the probe is a valid request.

No findings. The change is tightly scoped, mirrors established patterns, and is well-tested.
