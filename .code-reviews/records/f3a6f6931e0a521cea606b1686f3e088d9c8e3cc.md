## Summary

Platform-admin T3 adds the owner-link flow. A super admin issues an organization
owner invitation (reusing the website-invitation token helpers: 32 random bytes,
SHA-256 stored); the `/invitations/lookup` and `/invitations/accept` public
routes now fall through to owner-invitation handling when the token is not a
website invitation, and accepting elevates the new owner to Administrator on
every existing site in the organisation inside one transaction with the user
creation and invitation delete.

The security posture is sound: tokens are high-entropy, stored only as SHA-256,
`z.strictObject` prevents mass assignment on create/issue, email always comes
from the invitation row (never from the request body), and both the invitation
row and the organisation row are locked `FOR UPDATE` before the accept-time
checks. Race conditions (second accept, concurrent accepts, email taken between
check and insert) are covered by the test suite and appear correctly handled.
The `isUserEmailTaken` catch-and-map and the Postgres pessimistic lock on both
rows protect against the user-create race. No new HTTP routes were introduced,
so the tenant-isolation table correctly does not need an entry.

Re-review (2026-11-12): all four previous findings have been resolved by
extracting shared helpers (`src/database/unique-email-violation.ts`,
`src/invitations/invitation-token.ts`, `src/invitations/new-account.ts`),
collapsing the duplicate `findByTokenHash` round-trips in the lookup/accept
service paths, and removing the re-export of token helpers from the invitations
service. Imports in `src/cli/run-demo.ts`, `src/invitations/invitations.service.ts`,
`src/invitations/invitation-acceptance.repository.ts`,
`src/platform-admin/platform-admin.service.ts` and
`src/platform-admin/platform-admin.repository.ts` all go through the new shared
modules, and no duplicate copies remain.

Note: `git fsck` reports several missing blobs in this worktree's git objects,
so `git diff --cached` renders the modified files as deletions. The review was
done against the staged working-tree content directly.
