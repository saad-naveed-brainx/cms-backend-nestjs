## Summary

Stack: NestJS (NestJS 12 + TypeORM, API repo). The change is test-only plus a doc update — no `src/` code is touched.

Scope reviewed:
- `test/support/two-clients.ts` (new): a reusable "world" for the tenant isolation sweep. It stands up two real clients (Acorn and Birch) through the production provisioning/invite/media/content paths, deliberately colliding on the same page path (`/about`), draft path (`/draft`), content type path (`/recipes`), and one person (`pat@both.test`) who belongs to both sites. Also exports `fingerprint()` (per-site hash of every row in every `site_id`-bearing table, discovered via `information_schema`), `tenantTables()`, and `ownedIds()`.
- `test/tenant-isolation.e2e-spec.ts` (new): the FND-03 / GOV-08b invariant. A single `ROUTES` table is cross-checked against what Nest actually declares at runtime (reading `@Public`, `@SiteScoped`, `@RequirePermission` from controller metadata), then each side attacks the other through every closed route — spelled site headers, foreign ids under one's own header, smuggled `siteId`/`site_id` in body, multipart form, and query string. The victim is fingerprinted before and after every attack. Public doors (`/public/site`, `/uploads/:siteId/:name`, `/sites/resolve`, `/public/preview`), invitations, and preview links get the same treatment, plus a focused "hunt" section (filters by foreign type id, mixed-site role ids, same-email invitations, member removal, site deletion).
- `CLAUDE.md`: invariant 7 renamed to point at the new test, and a new gotcha section documents the table and the author's responsibility to mark `ids`/`disposable` (B-43) when adding a route.

Overall this is high-quality test infrastructure: real app, real database, real tokens, no mocks (as HUNT.md's "proof the checks can fail" demonstrates — four deliberate code regressions were caught). SQL in test helpers uses parameterised values for user-supplied inputs; the only string-interpolated identifiers (table and column names) come from the hardcoded `ROUTES` definitions or from `information_schema`, both trusted sources. Typecheck passes. The CLAUDE.md edit is consistent with the shipped test and with D-052.

Re-review: both previously-raised Low findings have been resolved in the staged code — the `mediaName` extraction now has an explicit null check that throws at setup, and the `toBeGreaterThan(25)` floor is now preceded by a comment stating today's route count (32) and the intent of the floor.

No open findings.
