## Summary

Stack: NestJS 12 + TypeORM + Zod + Postgres. Scope: adds `POST /organizations`
(organizations T2 / D-056) so any signed-in person can create an organization they
own, and relocates the `GET /organizations` listing into a dedicated
`OrganizationsController`/`OrganizationsModule`. Supporting changes:
`ProvisioningRepository` gains a narrow `createOrganization(ownerId, name)` write
method; `ProvisioningService.createOrganization` validates input via a new strict
Zod `organizationInputSchema` (trimmed, 1–100 chars, NUL-free, no extra fields);
the ad-hoc error-mapper in `site-creation.controller.ts` is extracted to a
reusable `provisioning/http-errors.ts` and shared by both controllers; the
pinning test for `ProvisioningRepository` is updated from two methods to three;
`CLAUDE.md` is updated to describe the new route and invariants.

The code closely follows established project patterns: strict Zod on the
boundary, `@CurrentUser` auth-user injection, global auth guard with no
`@Public()` on sensitive routes, single-method / single-concern desks, the owner
is read from the authenticated principal (never the body), and `strictObject`
guards against mass-assignment of `ownerId`/`id`/`siteId`. Tests are real-DB
e2e, cover happy path, validation (including NUL), mass-assignment refusal, 401
without a token, idempotent naming (duplicates allowed), and regression of the
sibling site-creation and `/auth/me` flows.

No security, correctness, or data-integrity issues found. No findings to raise.
