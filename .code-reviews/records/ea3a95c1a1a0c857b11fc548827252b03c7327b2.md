## Summary

Stack: NestJS (CLI script and e2e test only — no HTTP routes, no entities, no
migrations in this diff).

Scope: the demo CLI (`src/cli/run-demo.ts`) gains a pre-flight check that the
`--email` account cannot also appear in any client's `people` list, plus a
end-of-run warning when a partial failure may have created accounts. A new
e2e test (`UC-UR-27`) covers both the author-not-in-people refusal and the
email-clash refusal, and asserts that neither path writes a row — even with
`--replace`. Three README/CLAUDE.md entries are reworded to describe the new
behavior.

Overall the change is tight, well-placed, and well-tested:
- The pre-check runs after file parsing but before `openApp()`, so a refusal
  cannot leak side effects (consistent with the "checked before anything is
  made" invariant called out in `CLAUDE.md`).
- `args.email.trim().toLowerCase()` matches what the Zod `email` schema at
  `src/cli/run-demo.ts:81` already does to `people[].email`, so case/whitespace
  variants are compared on even ground. The test exercises `Owner@Refused.test`
  specifically to prove it.
- The new test's `everyRow()` snapshot is a stronger assertion than most of
  the existing CLI tests — it would catch a future regression where a bad
  author somehow slipped past the Zod `superRefine` and reached provisioning.
- The partial-failure warning only fires on real in-flight failures (after
  `openApp()`); the two early-exit paths above it return before the final
  block.

No cross-repo contract concerns: this is a CLI-only change, nothing in `web`
or `admin` depends on it.

No single-repo correctness, security, or maintainability issues found.
