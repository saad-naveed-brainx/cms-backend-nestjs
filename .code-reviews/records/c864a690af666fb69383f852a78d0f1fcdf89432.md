## Summary

Platform-admin T1 (D-062): introduces the super-admin flag (`users.is_platform_admin`),
the `create-super-admin` CLI (grant and revoke), the `PlatformAdminModule`
(`PlatformAdminService` + `PlatformAdminRepository` + `PlatformAdminGuard`), the
`AddPlatformAdmin` migration, a new `OrganizationInvitation` entity (table created now;
routes land in T2–T5), a `suspended_at` column on `organizations`, and nullability on
`organizations.owner_id` (for organisations waiting on an owner invitation). `AuthService`'s
`PublicUser` and `toPublicUser` carry `isPlatformAdmin` so sign-in and `/auth/me` reflect the
flag. Tests cover the CLI end-to-end (real Postgres), the guard in isolation, the migration
up/down round-trip, the repository method surface, and the arg parser.

Stack: NestJS (detected from `@nestjs/core` in `package.json`). NestJS criteria applied
alongside the general criteria.

Observations:
- Password handling is clean: `--password` on the command line is explicitly refused;
  `SUPER_ADMIN_PASSWORD` env var only; generated passwords are 18 random bytes
  (base64url, 24 chars), hashed via `PasswordService` (scrypt), printed exactly once.
- `PlatformAdminGuard` reads the flag from the database on every request (via
  `PlatformRepository.findUserById`), not from the token — so revocation is immediate, as
  intended.
- `grantPlatformAdmin` runs in one transaction; `revokePlatformAdmin` is a single update.
- The nullable `ownerId` change is consistent across callers: every existing use either
  filters by a definite userId (`platform.findOrganizationsOwnedBy`,
  `site-removal.deleteOwnedSite`, `deleteEmptyOrganization`) or uses null-safe comparison
  (`organization?.ownerId === userId`, `'org.ownerId = person.id'` in SQL — NULL compares
  non-equal). No regression introduced.
- The repository surface is pinned by `platform-admin-repository.spec.ts`
  (`grantPlatformAdmin`, `revokePlatformAdmin`); adding a method is an explicit change.
- Migration down is intentionally strict: it will fail if an organisation is still waiting
  for its owner (SET NOT NULL on `owner_id`). Documented.
- `OrganizationInvitation` entity is added to `ENTITIES`/`index.ts` and its table is
  created now, but it has no service/repository consumer yet — this is deliberate (T2–T5
  will pick it up), and the migration round-trip test verifies the schema both ways.
- Profile shape change (`isPlatformAdmin` added to `user`) is reflected in both auth e2e
  tests; `[UC-PA-35]` pins the exact key set.
