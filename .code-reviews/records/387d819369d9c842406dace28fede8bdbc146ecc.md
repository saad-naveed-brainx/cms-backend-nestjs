## Summary

Two staged changes, both infra, no application code:

1. `.github/workflows/code-review-pr.yml` — new GitHub Actions workflow that reads `.code-reviews/ledger.jsonl`, aggregates per-commit scores for the commits in a PR, and posts/edits a markdown score comment. Runs on `pull_request` events, same-repo only (fork PRs are correctly skipped because their token can't comment). Uses `set -euo pipefail`, tolerates malformed ledger lines with `jq … fromjson? // empty`, and uses `GH_TOKEN: ${{ github.token }}` with least-privilege `contents: read` + `pull-requests: write`. No secrets in code, no shell-interpolation of untrusted input (branch names/SHAs come from GitHub context, flow through env vars quoted inside bash).

2. `.gitignore` — ignores `/.code-reviews/brainx-review.md` (the review pipeline's working file; the post-commit hook deletes it after copying into `records/`). Correct leading-slash anchoring to repo root.

The repo is NestJS per `package.json`, but neither file is Nest code, so the NestJS resource criteria largely don't apply here — this is a general CI/config review. Not a cross-repo change (only the api repo has staged changes).
